# Внешнее размещение

## Свой сервер: sad-slogov.dmdp.ru (основной путь)

Публикацией занимается `.github/workflows/deploy.yml`: на каждый push в `main`
общий workflow из [sites_configs](https://github.com/dnovichkov/sites_configs) собирает
образ `ghcr.io/dnovichkov/sad-slogov` и выкатывает его на сервер.

Образ — двухступенчатый (`Dockerfile`): `node:22-alpine` выполняет `npm run build`,
готовый `dist/` переезжает в `nginx:1.29-alpine` с конфигом `docker/nginx.conf`.
Сборка образа и есть проверка: `npm run build` — это `check.mjs`, `test.mjs` и копирование.

Контейнер наружу не смотрит (`docker-compose.prod.yml` без `ports`): TLS терминирует
Caddy из `sites_configs` и ходит в контейнер `sad-slogov` по внутренней сети `web`.
Маршрут `sad-slogov.dmdp.ru` и карточка на <https://projects.dmdp.ru/> заданы одной
записью в `projects.toml` того же репозитория; DNS отдельно настраивать не нужно.

Локальная проверка образа целиком:

```sh
docker compose -f docker-compose.prod.yml build
docker run --rm -p 8080:80 ghcr.io/dnovichkov/sad-slogov:latest
```

`/healthz` отвечает `ok` — по нему docker следит за живостью контейнера.

## GitHub Pages (зеркало)

Публикацией занимается `.github/workflows/pages.yml`: на каждый push в `main`
он выполняет `npm run build` и выкладывает `dist/`.

Pages уже включён с источником **GitHub Actions**. Отдельная ветка `gh-pages`
не нужна, `dist/` в репозитории не хранится — его собирает CI.

Сайт: <https://dnovichkov.github.io/sad-slogov/>. Подпапка работает: все пути
к файлам относительные. Служебный лист иллюстраций `art-sheet.html` в сборку
не попадает и на опубликованном сайте отдаёт 404 — так и задумано.

Сайт будет публичным. Ограничить доступ средствами GitHub Pages нельзя —
про приватность смотрите раздел «Доступ и обновление».

## Загрузка готовых файлов

1. При необходимости выполните `npm run build`.
2. Загрузите **содержимое** `dist/` в корень сайта: рядом должны оказаться `index.html`, `app.js`, `curriculum.js`, `art.js`, `style.css`, `icon.svg`.
3. Откройте адрес сайта и начните занятие.

Node.js на хостинге не нужен. Можно разместить сайт в подпапке: пути к файлам относительные. Адрес подпапки должен оканчиваться `/`.

## Сборка из Git на хостинге

Создайте свой репозиторий из папки `sad-slogov` и подключите его к хостингу статических сайтов.

| Настройка | Значение |
| --- | --- |
| Тип проекта | Статический сайт / Other |
| Корневая папка | Папка с `package.json` |
| Команда сборки | `npm run build` |
| Папка публикации | `dist` |
| Установка зависимостей | Не требуется |
| Команда запуска сервера | Не требуется |
| Переменные окружения / API-ключи | Не требуются |

Если хостинг требует команду установки, `npm install` допустима: внешних зависимостей нет. `npm ci` требует lock-файл, которого в этой копии нет.

## Свой веб-сервер

Укажите в конфигурации веб-сервера корневой каталог с содержимым `dist/` и индексный файл `index.html`. Файлы должны отдаваться с обычными MIME-типами для HTML, JavaScript, CSS и SVG. Перенаправление клиентских маршрутов не требуется: приложение работает на одной странице.

Для внешнего адреса используйте HTTPS. Команды `dev` и `preview` предназначены для локальной проверки.

## Доступ и обновление

Встроенной авторизации и серверного хранения нет. Для приватного размещения настройте ограничение доступа средствами хостинга. `noindex` и скрытая ссылка не заменяют авторизацию. `private: true` в `package.json` запрещает случайную публикацию npm-пакета и не ограничивает доступ к сайту.

История и настройки хранятся у каждого посетителя в браузере. Новый домен означает отдельное хранилище: занятия с github.io на sad-slogov.dmdp.ru не переезжают.

При обновлении выкладывайте весь `dist/`: имена файлов не содержат хешей. Настройте повторную проверку кэша для HTML, JS и CSS или очистите кэш хостинга, чтобы посетители получили согласованную версию.

После публикации проверьте начало и завершение серии, подсказки, паузу, настройки взрослого, сохранение после перезагрузки и нажатия на телефоне.
